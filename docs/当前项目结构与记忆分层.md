# 当前项目结构与记忆分层

本文描述合并整理后的当前状态。核心原则：**`src/agent_runtime` 是唯一正式 agent loop**；Feishu、Memory、Trace 都通过 `src/tool_integration` 暴露为工具；旧 `pmo_mvp` 本地 JSON demo 已移除。

## 结论

| 结论 | 说明 |
| --- | --- |
| 正式 agent loop 在 `src/agent_runtime/` | `AgentRuntime.run_agent()` 创建并驱动 `agent_runtime.session.AgentSession`。 |
| 正式工具执行在 `src/tool_integration/` | `ToolIntegrationExecutor.call_tool()` 负责权限校验、调用工具、把工具调用写入 `session.steps`。 |
| 飞书工具在 `src/feishu_adapter/` | Adapter 只封装飞书 API，不感知 Agent 业务角色。 |
| AgentContext 在 `src/agent_runtime/context.py` | 管理运行时上下文窗口、scratchpad、相关记忆检索和 compact summary。 |
| Memory 在 `src/agent_runtime/memory/` | SQLite/FTS store、checkpoint、process log、doc chunks、memory toolset 都已迁入正式 runtime。 |
| Tool 扫描默认覆盖两处 | `src/feishu_adapter` + `tool_integrations`，所以 Feishu tools 和 memory tools 默认一起注册。 |
| 点记忆仍在工作区文件 | Agent 点记忆是 `agents/*/AGENT.md`；项目点记忆是 `projects/*/PROJECT.md`。 |

## 正式运行链路

```text
scripts/run_mvp_demo_chain.py
  └─ build_runtime_with_tool_integration(root)
       ├─ load_runtime_config(root)
       │    └─ load agents/*/agent.yaml
       ├─ build_tool_integration_executor()
       │    ├─ scan src/feishu_adapter
       │    └─ scan tool_integrations
       ├─ MVPAgentRegistry
       ├─ SimpleRuleQualityGate
       └─ CompositeTraceSink
            ├─ LocalJsonlTraceSink
            └─ MemoryTraceSink

AgentRuntime.run_agent(request)
  ├─ create_session(event, agent_name)
  │    └─ returns agent_runtime.session.AgentSession
  ├─ trace_sink.on_session_start(session)
  ├─ handler.run(session, payload)
  │    └─ tool_executor.call_tool(..., session)
  │         ├─ enforce agents/*/agent.yaml tool_policy
  │         ├─ ToolRuntime.invoke()
  │         └─ append ToolCallRecord into session.steps
  ├─ append Pydantic output into session.memory
  ├─ session.mark_success() / mark_failed()
  └─ trace_sink.on_session_end(session)
```

## AgentSession 与 AgentContext

当前正式 `AgentSession` 位于 `src/agent_runtime/session.py`。它是一个 run 内的热状态对象，生命周期由 `AgentRuntime` 管理。

它包含：

- identity：`session_id`、`run_id`、`parent_run_id`、`trace_id`
- scope：`project_id`、`agent_name`、`trigger_type`、`trigger_user`
- lifecycle：`status`、`started_at`、`ended_at`、`retry_count`
- loop trace：`current_step_index`、`max_steps`、`steps`
- short-lived memory：`memory: list[SessionMemoryItem]`
- IO and errors：`input_record_ids`、`output_records`、`read_sets`、`write_sets`、`errors`、`final_summary`

`AgentContext` 位于 `src/agent_runtime/context.py`。它是 runtime/context 管理层，不是短期记忆本体。当前 runtime 会为每次 run 创建 context，并支持两种 handler 形式：

- 旧形式：`run(session, payload)`
- 新形式：`run_with_context(context, payload)`

`AgentContext` 负责组装运行时上下文视图、维护 scratchpad、通过 `ToolIntegrationExecutor` 检索长期 memory、估算上下文预算，并在超过预算时生成 deterministic compact summary。compact 结果会写入 `session.memory`，随后可被 `MemoryTraceSink` 持久化到 checkpoint。

## 记忆分层

| 层级 | 当前实现 | 说明 |
| --- | --- | --- |
| 点记忆 | `agents/*/AGENT.md`、`projects/*/PROJECT.md` | Agent/system prompt 与项目稳定信息。 |
| 短期记忆 | `AgentSession.memory`、`AgentSession.steps` | 当前 run 内热状态；不直接放 SQLite。 |
| 上下文管理 | `AgentContext`、`ContextBudget`、`CompactSummary` | 控制上下文窗口、scratchpad、retrieved memories 和 compact summary。 |
| checkpoint | `agent_runtime.memory.AgentSessionCheckpoint` | `MemoryTraceSink` 持久化 runtime session 的摘要和 scratchpad。 |
| 过程记忆 | `process_events`、`traces/*.jsonl`、`session.steps` | 每次 run 的过程日志、工具调用和错误轨迹。 |
| 项目上下文 | `project_members`、`project_artifacts`、`PROJECT.md` | 记录项目成员职责和外部 artifact。 |
| 长期记忆 | `memories` + FTS5 + 可选 vector backend | episodic / reflective / procedural 经验，支持 `project_id`、`agent_id`、`run_id` 过滤。 |
| 文档记忆 | `documents`、`doc_chunks` + FTS5 | 用户上传文档的 chunk 检索。 |

## Memory Tool 接入

`tool_integrations/memory_tools.py` 把 `MemoryToolset` 注册进正式 `ToolRegistry`。Agent handler 使用它时必须走：

```python
await tool_executor.call_tool(
    "memory_search",
    {
        "query": "阻塞任务风险",
        "agent_id": str(session.agent_name),
        "project_id": session.project_id,
        "top_k": 5,
    },
    session,
)
```

这样 memory 调用也会被 `ToolIntegrationExecutor` 审计到 `session.steps`，并受 `agents/*/agent.yaml` 的 `tool_policy.allowed_tools` 控制。

已暴露工具：

- 长期记忆：`memory_write`、`memory_search`、`memory_get`、`memory_reflect`、`memory_weight_update`、`memory_evict`
- 点记忆：`profile_write`、`profile_read`
- checkpoint：`session_start`、`session_finish`、`session_get`、`session_list`
- 过程记忆：`process_log`、`process_search`
- 项目上下文：`project_context_upsert`、`project_context_get`
- 文档：`doc_ingest`、`doc_search`

`session_start` / `session_finish` 在正式架构里只表示 checkpoint 工具，不创建或驱动运行态 `AgentSession`。

## Feishu Tool 接入

Feishu tools 由 `src/feishu_adapter/*.py` 的 `register(registry, **kwargs)` 注册。默认工具扫描会加载这些模块，业务 handler 只通过工具名调用，例如：

- `feishu_bitable_search_records`
- `feishu_bitable_create_record`
- `feishu_bitable_update_record`
- `feishu_drive_list_folder`
- `feishu_docx_*`

业务 Agent 不直接 import `feishu_adapter`。唯一例外是运行脚本中的少量 bootstrap/字段探测逻辑；正式 handler 路径应继续走 `ToolIntegrationExecutor`。

## 配置和运行

默认扫描目录：

```text
src/feishu_adapter,tool_integrations
```

可用 `HIVEMIND_TOOL_SCAN_DIRS` 覆盖。

默认 memory DB：

```text
runtime/memory.db
```

可用 `HIVEMIND_MEMORY_DB_PATH` 覆盖，`MemoryTraceSink` 和 `memory_tools.py` 共用该配置。

运行测试：

```bash
python -m pytest tests/ -q
```

运行 MVP 链路：

```bash
python scripts/run_mvp_demo_chain.py --skip-coordinator-write
```

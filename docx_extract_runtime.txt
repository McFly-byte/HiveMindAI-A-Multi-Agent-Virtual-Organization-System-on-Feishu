P114: C. Agent Runtime 当前实现对齐版（补充修订）
P115: 本节基于当前仓库 src/agent_runtime、agents/*/agent.yaml、prompts/shared 与 tests 的实际实现，对前述设计笔记进行落地化修订。当前 Runtime 的定位不是完整平台，而是支撑 Demo 可复现、可审计、可回放的强类型契约层与生命周期骨架。
P116: - Base 是唯一业务事实源。Runtime 只保存一次运行所需的短期状态和审计信息，不把关键业务状态长期保存在 AgentSession、本地文件或全局变量中。
P117: - Agent Runtime 不实现底层 Feishu API、Tool、Memory 或 LLM 客户端，只定义它们与 Agent 交互的数据结构、配置边界和 Protocol。
P118: - 所有 Agent 输出优先使用 JSON，并通过 Pydantic schema 校验后再进入后续流程。
P119: - 每次运行必须能追踪 run_id、project_id、agent_name、trigger_type、input_records、output_records、tool_calls、llm_calls、errors 和 status。当前 Session 模型已覆盖这些字段，但 AgentRunRecord 落库投影还未完整包含 steps/tool_calls/llm_calls。
P120: 1. 当前代码结构
P121: 2. Runtime 生命周期
P122: - 外部触发被规范化为 AgentTriggerEvent，包含 event_id、event_type、trigger_type、project_id、target_agent、trigger_user、user_intent、changed_fields、input_records、scope、timestamp、metadata。
P123: - Coordinator 或调用方构造 AgentCallRequest，指定 agent_name、reason、parent_run_id 和 input_payload_ref。
P124: - AgentRuntime.create_session 根据事件和 AgentConfig 创建 AgentSession，并生成 session_id、run_id、trace_id；input_records 当前投影为 input_record_ids。
P125: - AgentRuntime.run_agent 将 session 状态置为 running，调用 TraceSink.on_session_start，然后通过 AgentRegistry 获取 handler 并执行 handler.run(session, input_payload_ref)。
P126: - handler 成功返回后，Runtime 读取 output.summary 写入 session.final_summary，并将状态置为 success；发生异常时写入 RuntimeErrorInfo，状态置为 failed，并调用 TraceSink.on_error。
P127: - 无论成功失败，finally 都调用 TraceSink.on_session_end，保证审计链路闭合。
P128: - 注意：tool_executor 和 quality_gate 已作为依赖注入到 AgentRuntime，但当前 run_agent 尚未直接调用；实际工具调用、LLM 调用和 Quality Gate 执行应由后续 handler / service 层接入并回填 session.steps。
P129: 3. 审计字段与当前落点
P130: 4. Agent 配置与 Prompt 加载
P131: - 每个 Agent 通过 agents/<name>/agent.yaml 声明 agent_name、role、display_name、description、workspace_path、prompt、model、runtime_limits、tool_policy、write_policy、hook_policy、input_schema、output_schema。
P132: - load_agent_config 使用 YAML + Pydantic 校验单个 agent.yaml；load_all_agent_configs 扫描 agents/*/agent.yaml；load_runtime_config 汇总成 RuntimeConfig。
P133: - load_agent_prompt 会把 Agent 自己的 AGENT.md 与 shared_prompt_paths 中的共享规则拼接，当前共享规则包括结构化输出、证据和禁止幻觉等。
P134: - ModelConfig 只保存 provider/model_name/temperature/max_tokens/timeout/json_mode，不创建真实 LLM 客户端。当前配置使用 deepseek-chat，json_mode 为 true。
P135: - RuntimeLimits 当前 Coordinator 为 max_steps=5、max_tool_calls=20、max_llm_calls=3；业务 Agent 多为 max_steps=4、max_llm_calls=2。
P136: 5. Agent 边界
P137: 6. 与 Feishu、Tool、LLM、Memory 的边界
P138: - Feishu Base：Runtime 只定义 BaseRecordRef、RecordCreate、RecordPatch、OutputRecordRef、ProjectManifest 等结构，不实现 Feishu HTTP/SDK 调用。真实读写由工具层实现，结果回填 read_sets、write_sets、output_records。
P139: - Tool：Runtime 只定义 ToolExecutorProtocol.call_tool 和每个 Agent 的 tool_policy.allowed_tools / denied_tools。工具名当前是配置字符串，例如 base_query_tool、agent_call_tool、quality_gate_tool、trace_tool。
P140: - LLM：Runtime 只定义 LLMClientProtocol.generate_json 和 ModelConfig；不持有 API Key，不创建客户端，不直接发起模型调用。LLM 输出应按 schema_name 做 JSON 校验。
P141: - Memory：AgentSession.memory 是单次 run 的短期记忆，用于当前执行过程传递上下文；MVP 不建设长期记忆系统，关键业务事实仍以 Base 为准。
P142: - Quality Gate：quality_gate.py 已定义 QualityGateRequest / QualityGateResult / QualityCheckItem。当前配置要求写回必须过 Quality Gate，但具体检查实现和与写回工具的串联仍待实现。
P143: 7. AgentRuns 表与可回放要求
P144: AgentRuns 是运行审计表，应沉淀每次 Agent 执行的最小可回放信息。当前 AgentRunRecord.from_session 已能从 AgentSession 投影 run_id、parent_run_id、session_id、trace_id、project_id、agent_name、trigger_type、input_record_ids、output_records、read_sets、write_sets、reasoning_summary、status、error_type、error_message、started_at、ended_at。
P145: - 短期应补齐：input_tables、executed_actions、evidence_summary 的赋值逻辑。
P146: - 如要完整回放，应扩展 AgentRuns 的 JSON 字段或关联明细表，保存 session.steps、tool_calls、llm_calls、错误列表和关键 prompt/output 摘要。
P147: - 不建议把完整 prompt、完整模型输出或敏感业务数据无筛选写入 AgentRuns；当前 ToolCallRecord / LLMCallRecord 使用 summary 字段，方向是正确的。
